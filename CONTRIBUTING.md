# Contributing

Contributions are welcome while the project is in beta.

1. Open an issue describing the behavior or contract change.
2. Keep changes provider-neutral and avoid organization-specific identifiers.
3. Add or update deterministic tests.
4. Run `npm run validate` and the PowerShell package validator.
5. Submit a focused pull request and document security or compatibility impact.

Do not include transcripts, credentials, personal paths, internal URLs, or
proprietary ticket data in fixtures, issues, or pull requests.
